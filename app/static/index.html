How it decides

The model only reads. Fixed rules decide. A person approves.
01 · Read

Transcribe the inbox

Each email or PDF becomes invoice fields, each with the exact quote that states it. Requests to change bank details are flagged, never applied.

02 · Verify

Vendor check and identity

Each vendor is proven real, active and run by its director, and screened against the news with namesakes cleared (5.1 + 5.2, live Crustdata, cached per vendor). The invoice's sender must be that same company: no look-alike domain, a valid GSTIN that matches the vendor master.

03 · Check

Bank, duplicate, PO

Same verified account, and a bank-change request triggers a drafted call-back to the contact on file (never sent by the desk); not an invoice already seen in another format; within 1% of the PO, and the PO not already billed.

04 · Approve

A person decides

Clean invoices and held ones both wait here. A person can approve or reject; nobody can edit a result.

05 · Pay once

Idempotent payout

The payment key is saved before the provider is called. Kill the process anywhere: on restart the same key is reused, so the vendor is paid once.

06 · Show the work

Replayable audit trail

Every fact links to its record with field and date, every step is an event, every call has a cost line.
